# OpenETL data lab (real public data)

Five databases in Docker. Each one holds several tables / collections / indices, one OpenETL job per table, and every
byte of data is **downloaded from the internet** by `scripts/download.sh`. Nothing is generated or invented locally.

| Database (container, port) | Table / collection / index | Source data (downloaded) | Records |
|---|---|---|---|
| PostgreSQL 16 (`openetl-lab-postgres`, 5433, user/pass `lab`) | `apache_logs` | Apache error log, loghub (Zenodo), 56k lines | 1,414 |
| | `ssh_logs` | OpenSSH auth log, loghub, first 200k lines | 5,659 |
| | `books` | 8 Project Gutenberg novels | 1,997 |
| ClickHouse 24.8 (`openetl-lab-clickhouse`, 8123, `lab`/`lab`) | `linux_logs` | Linux syslog, loghub | 1,085 |
| | `diamonds` / `taxis` / `flights` | seaborn-data CSVs (54k / 6k / 144 rows) | 753 / 175 / 2 |
| MongoDB 7 (`openetl-lab-mongodb`, 27017) | `posts` `comments` `todos` `users` `albums` `photos` | JSONPlaceholder, one document per JSON object | 100 / 500 / 200 / 10 / 100 / 5,000 |
| | `countries` | mledoze/countries on GitHub | 276 (250 countries) |
| Elasticsearch 9.3 (`openetl-lab-elasticsearch`, 9200) | `hadoop_logs` | Hadoop container logs, loghub (978 files) | 20,316 |
| | `healthapp_logs` | HealthApp mobile log, loghub, first 200k lines | 9,543 |
| | `wiki_pages` | 25 Wikipedia pages (HTML) | 653 |
| Qdrant 1.12 (`openetl-lab-qdrant`, 6333) | `rfcs` | 10 IETF RFCs | 716 |

No dataset is loaded twice: each file goes to exactly one table. (The 26 repeated texts in `books` are boilerplate that really
repeats across Gutenberg books.) `reset.sh` empties every target before a full load, so re-running never duplicates.

## Run it
```bash
docker compose up -d
./scripts/load.sh               # download -> prepare -> empty targets -> run all 18 jobs (about 3 minutes)
./scripts/load.sh mongo_        # re-run only the jobs whose name contains "mongo_" (targets are not emptied)
./scripts/verify.sh             # read a real count and a real row back from every table
HDFS=1 ./scripts/download.sh    # optional: also fetch the 186 MB HDFS log archive
LINES_PER_PART=40 MAX_LOG_LINES=1000000 ./scripts/load.sh   # bigger load: more log lines
```
Per-job output is in `logs/<job>.log`. Pipelines in `pipelines/` are generated by `scripts/gen_pipelines.py`; edit its JOBS list to add a table.

## Prepare steps (why they exist)
OpenETL is a document extractor, so some inputs need cutting first. Lines and objects are copied verbatim.
- `split_logs.py`: one 5 MB log came out as just **two chunks (1.7 MB and 3.4 MB)** because the chunker has nothing to split a log on.
  Logs are cut into 40-line parts. Hadoop is already one file per container.
- `split_json.py`: a JSON array of 500 comments came out as 61 text chunks. Each element is written to its own file instead, giving one record per object.

## What I found
- **CSV is stored as text tables, not rows.** The 54,000-row diamonds CSV is 753 markdown-table chunks, the 144-row flights CSV is 2.
  Values are present but not queryable as columns. The `csv_rows` transform exists but the ClickHouse sink's fixed layout drops its values.
- **Qdrant stores text and metadata, not real embeddings** (vector size 384, the sink says so itself). The text is in payload key `content`.
- `wiki_pages` finishes `PARTIAL` with 1 warning (`Optical_fiber.html` fails with an OpenETL `EquationData` validation error, a bug in the HTML parser; the other 24 pages load); see `logs/es_wiki_pages.log`.
- Elasticsearch's `_count` is exact; `_search` totals are capped at 10,000 unless `track_total_hits` is set.
- Pipeline 06 (reports copied to Relata) was removed: it duplicated the Postgres data.
- A `.env` copied from the repo's `.env.example` breaks the HTTP source (`EXTRACTOR_HTTP_MAX_BYTES=   # comment`), so jobs run from this folder.

Folders: `downloads/` (raw data, ~265 MB), `pipelines/`, `scripts/`, `logs/`, `state/` (OpenETL run history, safe to delete).
